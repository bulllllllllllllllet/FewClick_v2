## 对照如何命名才准确

SAM、SAM-Med2D、SAM2 和 WSI-SAM 本身的本图提示接口不等同于跨 patch 语义迁移。主表应明确标为“方法 + 自动支持→查询迁移桥（本研究适配）”，并披露桥的训练参数和自动提示来源。不得将其称为原作者原生远端能力。

自动 query 点允许从支持证据和 query 图像推导；它们不增加人工点击数，但算法计算、数量和成本必须披露。不得借 query GT 判定目标是否存在、生成点/框或挑选区域。SANSA 保留其原生记忆传播路径，HG-mix 保留自己的稠密迁移路径。

视野按各自已固定接口保留并列账：SAM/SAM2 旧迁移桥使用三尺度对齐特征，WSI-SAM 两视野，SANSA fine 单视野，HG-mix 三物理视野且每图7次共享 encoder 调用。SAM-Med2D 的原生预处理及桥的输入信息先在工程合同核定。不能把相同标签预算写成相同视野/分辨率/计算。

## 执行次序、资源与边界

第一批优先 SAM、SAM2、WSI-SAM 三个已有适配接口；SAM-Med2D 完成原生/桥工程验证后进入第二批。SANSA、HG-mix 不重训。建议未来执行时最多3个自有训练 worker、总自有GPU worker不超过6；六卡按实际空闲显存及峰值选择，共享允许，至少12288MiB且满足实测峰值余量。门控通过后分片推理利用释放卡，不终止他人进程。

这是建议调度，不是本轮启动授权或对已有运行的修改。新训练与全部推理输出进入新的时间戳 NFS 目录。每臂 functional→fresh4→fresh2375→evalgate→11000→重评分自动串联，失败停止、无自动换配方。用真实 gate 计时估算 SAM 耗时；不从 HG 的速度直接推算全部 SAM。

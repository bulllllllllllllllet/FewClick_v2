# 边界细化诊断后的优化优先级

- 问题：当前点细化的失败应优先改结构、数据还是监督目标？
- 依据：细化233341的1024例正式负结果；边界细化负结果诊断122728的24val/12train机制检查；当前coarse的96k更新预算对照。对应源码point_boundary_detail、train_point_boundary、continue_dense_boundary.dense_loss；没有新的外部方法效果比较。
- 已证实：本版没有保留原边界带监督，且把整图Dice换为采样点Dice；训练/推理位置分布不同；诊断样本中改坏像素多于修好像素，缩小修正后仍未反超。未证实：这些因素各自的因果贡献、完整多尺度结构能带来多少提升。
- 推荐顺序：先保持当前点头/冻结coarse，分开做目标函数与采样位置的小对照；首先对照恢复边界带监督，固定采样不变；再单独对照采样点Dice与整图Dice，其他损失不变；再固定目标检查训练位置与推理选区匹配。记录实际监督点数、训练步数及耗时，不把更多点/更多计算的收益误报为策略本身。待确认方向后，再组合有效修改。
- 结构备选：使用未经固定分组平均的预训练浅层及中层特征、构建完整多尺度解码器，与当前128px coarse保持相同提示/数据/验证协议。先真实smoke再正式对照；此文不确定具体FPN配置，也未启动实现或训练。
- 暂不优先：扩大到37k、继续延长当前点头训练、单纯增加推理点数。原因分别是同预算扩量尚无明确优势、原8轮未反超、现有选区内净损伤仍为正。并非否定这些方向在后续改进后的价值。
- 预期收益：先恢复可靠的细化方向，减少错误翻转；不承诺结构改动一定提高BF1。
- 风险：多因素混改会掩盖原因；整图损失/更多监督点提高训练开销；更强特征增加缓存和点击时延；开发val已有选模及历史encoder暴露。
- 验收：相同1024开发val相对coarse BF1@2≥+0.01，macro/micro Dice≥coarse−0.002、可信提示违约不增加，逐类/107空间块配对区间、固定最后轮和最佳轮均报；最终仍需真实连续点击及未暴露区域评价。小诊断集不用于替代这一门槛。
- 当前状态：仅完成检查与建议归档，未启动后续训练；保留matched96k epoch31为最佳开发候选，默认J5未变。

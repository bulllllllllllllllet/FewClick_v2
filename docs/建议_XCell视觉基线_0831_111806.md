# XCellFormer 视觉基线对照建议

## 问题

此前 RNA 小实验中的“视觉特征”是颜色、纹理和细胞几何的手工特征，不能代表 FewClick v4 的实际细胞视觉编码器。需要判断 RNA 的增益是否仍存在于真实的 `CTransPath -> XCellFormer reg-64` 特征之上。

## 依据

- `docs/建议_RNA特征小实验_0831_022013.md` 与 `docs/运行记录_RNA打乱对照_0831_023421.md`：已固定 COAD Xenium 同一 H&E 窗口、细胞—RNA 配对、分子标签和四块空间交叉验证方案。
- `benchmarks/v4/phase_3_cell_region/tools/extract_xcell_features.py`：v4 的细胞视觉链路是 soft-attention 细胞裁剪、CTransPath-768 和 XCellFormer 的 `reg-64` 输出。
- 历史权重 `/home/zhaoyh/FewClick/module/checkpoint/ctranspath.pth` 与 `he_model_best.pth`：只读使用，不复制或改写。

## 建议

在已产生的 1,200 个 RNA 配对细胞中，按四个 750×750 空间区域各确定性选取最多 255 个细胞；255 是历史 XCellFormer 的 token 上限。以 Xenium 边界多边形生成实例掩码后，运行 v4 同款 soft-attention、CTransPath 和 XCellFormer `reg-64`，再按原四块空间留出法比较：手工视觉、XCell 视觉、XCell 视觉加 RNA、XCell 视觉加打乱 RNA。

## 备选方案

- 继续只用手工视觉特征：快速，但无法回答“原始算法”的实际指标。
- 直接让 1,200 个 token 同时输入：不符合历史模型 `max_cells=255` 合约。
- 重新训练 XCellFormer：需要独立训练/验证集和更长时间，不是当前基线验证所需。

## 预期、风险与验收

- 预期：获得真实预训练视觉编码器上的可解释基线；RNA 若仍显著优于打乱 RNA，才说明增益不只是手工视觉弱造成。
- 风险：XCellFormer 权重来自其他训练域；四个区域各自编码会保留区域内上下文，因而结果是“兼容性基线”，不是最终 FewClick 分割指标。
- 验收：完整载入两个历史 checkpoint；每个保留细胞取得有限的 64 维 `reg-64` 特征；四种空间 CV 指标及真实/打乱 RNA 对照写入独立 artifact。

# FewClick_v2：跨服务器 Agent 复现交接

日期：2026-10-22。**先复现已训练权重的推理和评分，再考虑重新训练。** 当前交接对象是四域、代表性内部点击重新训练的C3：fine_only J5 + 74维细胞输入 + 像素位置软取region token + dense128。实际评估是512×512 patch支持—查询；支持/查询可以来自不同WSI，这不等于整张WSI分割已经验收。

## 1. 接手 Agent 按此顺序执行

1. 拉取包含本文件、新复现入口及附件的Git提交，建立对应环境。
2. 检查是否共享同一NFS；不共享则复制实际依赖并建立路径映射。
3. 固定20例验收通过后，再复现完整960验证，保留代码版本、环境、资产SHA、输出及差异。
4. 只有用户要求重新训练时，才迁移全量输入、通过训练门控并启动训练。不要把重新训练取得相近成绩与重放同一权重混为一谈。
5. 失败先诊断，不静默替换权重、改点击/阈值、重新选图或放宽校验。

本轮20k训练已完成，无后台训练。14000是按既定综合指标选出的最佳，20000是最新末轮；没有替换历史部署默认权重。泛癌种盲测、PUMA和完整WSI均尚未验收。

## 6. 实际架构与新图推理合同

```text
support RGB/cells → region encoder + cell fusion ──┐
support正负点击 → 点击处soft assignment混合token → prompt task
query RGB/cells → region encoder + cell fusion → task匹配/region graph → base mask
                                  deep/shallow/semantic + base/uncertainty/task
                                                        → dense128 → 512概率
```

DeepLabV3-ResNet50骨干、64个soft region、token维度256。保留12通道CRC语义作为中间特征；最终是**由提示定义的二值mask**，不是把新器官强制映射为CRC12分类。点击读取加权区域token，不是直接把点击RGB或组织GT类别ID送进模型。

DenseContextModel使用`DensePromptDecoder(high_resolution=True)`：深层、语义、base、uncertainty、prompt map与task调制融合，再接128×128浅层特征，输出残差上采样到512，加到base logit。当前fine_only无父尺度；不是历史六模块全尺度WSI入口。

| forward字段 | 形状 / 规则 |
|---|---|
| support/query的`image` | float32 `[1,3,512,512]`；RGB先/255，再ImageNet mean/std |
| `cells` | float32 `[1,N,74]`，每图独立，N≤255 |
| `cell_valid` | bool `[1,N]` |
| `total_cell_count` | float `[1]`，截断前核总数，不是保留N |
| prompts的`positive_xy`、`negative_xy` | float32 `[1,P,2]` / `[1,Q,2]`，支持图局部归一化x/y |
| `positive_mask`、`negative_mask` | bool `[1,P]` / `[1,Q]`；当前两种符号都至少1点 |
| `prompt_size_id` | long `[1]`，当前像素点任务=1 |
| `local` | 支持/查询是否同一图块身份 |
| `shared` | 同一图块且质量变体相同，编码能共享时才True |
| 输出 | `query.pixel_probability`为`[1,512,512]`，阈值.5 |

像素索引(x,y)转换为`((x+.5)/W,(y+.5)/H)`；WSI坐标先变换到支持图块本地，不能直接除512。归一化函数是`benchmarks.v4.phase_4_cross_scale.src.export_tokens.he_to_tensor`。

远端query只有support产生的task，query正负热图**全0**；不能把支持坐标照搬查询。query不用GT或用户点击。组织GT、类别ID、器官/癌种ID不属于forward输入。

无GT的用户交互使用`model.py`本身，不需要EpisodeCorpus；其接口草图是：

```python
model, _ = load_model(torch.device('cuda:0'))
payload = torch.load(checkpoint_path, map_location='cpu', weights_only=False)
model.load_state_dict(payload['model'], strict=True)
model.eval().requires_grad_(False)
# inputs={support:RGB/cells字典, query:独立RGB/cells字典, prompts:用户实际点,
#         local:bool, shared:bool}，按上表构造，不含GT/target_class。
with torch.inference_mode(), torch.autocast('cuda', dtype=torch.bfloat16):
    result = model(**inputs, with_support=False)
mask = result['query']['pixel_probability'][0] >= .5
```

这是API草图，需要导入torch/load_model并提供真实inputs；可直接运行的完整验收命令在第5节。`EpisodeCorpus.materialize`为评估读取GT、检查模拟点，不能误认为实际推理必须有query GT。NPZ读取`features`和`total`即可构造cells字段；完整prepare缓存还含instance/meta/reg供溯源。

Phase6源码按用途分目录，但公共导入维持原名，见其README；尤其不要误用旧`support_query_dense.encode_support`的centroid语义替代当前`DynamicFewClick.encode_support`的pixel语义。

## 7. 分辨率、细胞缓存及数据约束

按真实MPP处理，不能按“20x/40x”文件名或只resize512。目标约0.5µm/px、512平方、256µm视野；CRC实际MPP约[.499750,.500245]，OCELOT约[.499593,.499855]，IGNITE/TIGER=.5，实际值记录在manifest中。缺可靠MPP时不能声称尺度已经对齐。

`original/0.8/1.0`为同一物理视野的原质及降采样再恢复512的有效分辨率档，后两者不是图像边长倍率。RGB、细胞缓存必须是同一变体和SHA；不能拿原质cells配退化图。

74维：`[x,y,log1p(area_0.25MPP_equiv), nuclei_one_hot(7), image-predicted_XCell(64)]`。核类别全unknown0，因此0-based特征列3为1；没用组织GT赋核类型。64维由H&E经CTransPath/XCellFormer预测，不是实测RNA。

NPZ中的x/y已是归一化核质心，读取features后不能再除一次512。

新细胞当前用InstanSeg官方H&E nuclei TorchScript（模型自身.5MPP），沿用`prepare_cells.prepare_variant`和`fast_nuclei.CachedCenterCropper`：检测/裁剪几何约.25MPP网格，实际MPP换算面积，核ID前255再按y/x排序，128裁剪到224输入CTP/XCell。不要只跑分割后任意拼74维。InstanSeg权重SHA固定`0c724da169d507d8dd2e206ad3675a0b1566824eee6e20ad9a0ba916311d9dd0`。

预处理阅读：`multidomain_data/prepare.py`、`geometry.py`、`prepare_cells.py`、`fast_nuclei.py`。`external_cell_inputs.prepare_cells`是历史Cellpose路径，不是当前新缓存入口。已缓存的数据训练/评分不需重跑细胞模型；新图才需assets.new_preprocessing三个权重，其中CTP/XCell历史路径在`/home/zhaoyh/FewClick/module/checkpoint/`，也需别名或显式v5配置。

当前还没有“任意原始WSI直接输入当前dense模型”的通用生产CLI。新WSI需要物理坐标采样、细胞准备、缓存绑定、patch重叠融合/拼接和全片验证，不能直接用旧v4全片命令加载这个checkpoint就宣布复现当前全片效果。

  --steps 4 --warmup 2 --accumulate 4 --eval-every 2 --seed 20261021 \

门控验证真实forward/backward/更新、warmup→joint、串行梯度、分片验证、rank模型一致、保存重载。内部特征有FP16，即使关闭autocast也不是纯FP32对照。检查complete/无failure后才正式训练，**不要用4步门控权重初始化正式训练**。

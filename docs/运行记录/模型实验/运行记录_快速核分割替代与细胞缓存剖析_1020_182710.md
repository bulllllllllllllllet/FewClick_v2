# 快速核分割替代与细胞缓存剖析

- 用户授权：检索并尝试Cellpose以外更快的核分割模型，加速第二版细胞缓存。当前约8秒为完整Cellpose/裁核/CTP/XCell链路，不预先把全部耗时归给核检测。
- 依据：当前multidomain_data/prepare_cells.py及100份基准；旧CellViT Probe0917_160720；官方[InstanSeg](https://github.com/instanseg/instanseg)、[推理与物理尺度说明](https://instanseg.github.io/instanseg/inference.html)、[StarDist](https://github.com/stardist/stardist)、[CellViT推理](https://github.com/TIO-IKIM/CellViT-Inference)。权威数据catalogue和前处理记录1020_174937沿用。
- 候选优先级：InstanSeg brightfield_nuclei（轻量PyTorch/TorchScript，含后处理，模型自带训练MPP）；StarDist 2D_versatile_he（H&E专用，但需独立TensorFlow环境）；CellViT-HIPT-256（病理专用，可输出实例/类别，但旧缓存权重下载不完整、独立cellvit环境缺torch，不能声称可直接运行）。HoVer-Net作为备选，不假定后处理更快。
- 初期实验：固定最新版pilot的五源同图及原/低质版本，在GPU3、CPU4分段计时Cellpose检测、核几何、逐核裁图、CTransPath、XCell和总耗时；不覆盖GPU2在跑的基准，也不改全量RGB/GT导出。
- 输出根：`/nfs-medical3/zyh/fewclick_v2/multidomain_data/detector_speed_1020_182710/`；新源码在v5/multidomain_data，v4冻结。先真实小例再批量tmux，记录源码/权重哈希、PID、EXIT_CODE。失败明确停止，不自动切源/重试。
- InstanSeg采用官方release `instanseg_models_v0.1.1/brightfield_nuclei.zip`，15,054,316字节；仅下载该明场模型及元数据，ZIP CRC/路径安全/长度/可用发布摘要校验后加载TorchScript，不更改aligner依赖。官方完整TorchScript包含后处理，明确按其pixel_size重采样，输出实例映射回统一0.25MPP核几何坐标；不是使用荧光模型。
- 验证：所有候选输出同视野实例、坐标/面积单位一致，真实接入原CTP+XCell的74维合同；核身份保持unknown。速度报告同时给检测与全链，避免轻量模型检测很快但裁图仍慢。若逐核重复几何扫描是瓶颈，另测保持裁图像素完全一致的缓存中心优化，不未经验证替换现有缓存。
- 质量初筛：固定多器官图检查漏检/粘连/过分割并做同位置叠加；有条件时用OCELOT官方train细胞点做检测匹配，阈值按µm固定，不读取test或用PUMA核GT调参。不用与Cellpose一致率代替真值准确率，不因核数量更多就判更好。
- 采用条件：完整缓存显著提速且质量可接受，再确定新全量路线；不得把新检测器mask混入旧缓存身份。若只完成适配/速度，明确质量尚待验收，不宣称已经优于现有下游组织效果。
- 当前状态：检索/设计已记录，开始分段剖析与官方权重小规模试验。


## 完成结果（10-20 18:45）

当前结论：InstanSeg已真实接通原CTP/XCell及J5+dense输入，速度明显更快，但小样本核中心检测质量低于Cellpose，暂不替换默认检测器，也未启动全量新细胞缓存。已发现并验证保持原结果完全一致的裁核加速方案。

### 分段计时与同图比较

- 原100份Cellpose缓存基准已结束：worker3348909，100/100，818.81秒（含加载），单份处理均值8.131秒、中位9.303秒，所有数组落盘回读一致。
- 独立分段剖析`baseline_profile_1020_183201`：GPU3/CPU4，worker3413507，10份，EXIT_CODE=0。同步分段均值：核分割4.598秒、裁核5.790秒、CTransPath0.121秒、XCell0.004秒、几何0.026秒、padding过滤0.025秒。同步插桩、冷启动和CPU共享影响绝对值，不能与另一批8.13秒直接相减。
- 裁核瓶颈：旧`attended_crop`为每个保留核（最多255个）重新扫描整张实例图计算当前核的中心。`CachedCenterCropper`对每张实例图计算一次中心，保留原128²裁图、边缘填充、Gaussian注意力、量化与后续CTP/XCell。引用同一实例图期间不可原地修改标签；新实例图使缓存失效。
- `speed_1020_184049`：GPU3/CPU4，worker3455245，10份固定五源/原图和0.8质量配对，显式检测器暖身，三臂每图顺序一致，EXIT_CODE=0。完整检测→几何→裁图→CTP→XCell同步计算时间，不含RGB加载、压缩写盘、模型加载；并非NFS端到端吞吐。

| 处理方式 | 均值 秒/份 | 中位数 秒/份 | 相对原流程 |
| --- | ---: | ---: | ---: |
| Cellpose-SAM + 原裁核 | 9.067 | 8.727 | 1.00× |
| Cellpose-SAM + 缓存中心裁核 | 3.542 | 3.045 | 2.56× |
| InstanSeg + 缓存中心裁核 | 0.956 | 0.791 | 9.48× |

10份样本中，裁核加速前后实例、meta、reg、最终74维features及total全部逐元素完全一致。InstanSeg相对已加速的Cellpose仍快3.70倍，但实例数与形状会变化。InstanSeg按官方0.5MPP模型运行，结果映射到原检测输入约0.25MPP网格；原Cellpose按0.25MPP检测，二者是各自当前推理配置的对比。适配器按0.25MPP近似输入，来源窗口取整造成约0.0002MPP量级偏差，未宣称亚像素物理一致。

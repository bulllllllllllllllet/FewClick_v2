# 组织跨patch提示迁移

问题：既有原型是否能把一处组织提示用于另一处？依据学习曲线0922_004328，本轮冻结1000步模型，不训练、不选checkpoint，比较同一query上的local与cross提示。

沿用上轮108个val query，按相同WSI、目标组织和提示大小，在val中固定seed随机选择另一个support。三尺度上下文包围盒必须在至少一个轴上间隔512 level-0像素；找不到则明确排除，不改用重叠样本或其他split。正负support均从远处patch提供，不保留query中的提示输入。每个query的local与cross使用完全相同评分像素（排除原local提示区域），以免评分范围改变混淆效果。

Phase5的提示坐标与query区域坐标分支各自接收patch局部归一化坐标，不将support坐标误称为query内的点击。模型只做迁移诊断，没有跨patch训练，存在分布变化；若其表现下降，不能简单归因于架构。原型不使用xy。病例不作为分组依据；同一WSI对只检验片内跨区域能力，不是跨片/癌种泛化。任务目标由已有GT定义且query为目标存在任务，不能评价未知目标发现或缺失目标拒识。历史编码器暴露限制仍适用。

模块：`benchmarks/v5/phase_5_prompt_encoder/tools/evaluate_cross_patch_tissue.py`，基于84f7287及本轮v5新增源码，v4不改。输入`tissue_head_comparison_0922_004524`三个seed的三种模型1000步checkpoint及原空间清单。先`--max-queries 1`冒烟，再108 query；GPU1、aligner Python、CPU4线程，命名tmux与日志EXIT_CODE，输出`tissue_cross_patch_<timestamp>/`位于规定NFS根。保存配对、skip原因、支持坐标/槽位、source/checkpoint hash及逐任务掩膜/指标。

验收：全上下文间隔、同源同split、原query提示一致；support替换不改query token/坐标/真值；真实checkpoint推理有限；local可与上轮相同样本指标核对；成对报告Dice/IoU及覆盖，不静默略去失败类别。随后依据迁移下降幅度决定是否需要跨patch episodic训练。

### 标注预算敏感性检查

旧提示档位small/large允许不同实际正区域数，96对中只有70对正、负区域数都完全一致，26对档位一致但数量不同。因此全96对不能称作精确等标注预算。70对数量匹配子集的local→cross Dice：Phase5 0.492157→0.448458，单原型0.559590→0.529628，多原型0.562258→0.537311，方向一致；子集分布不同，不能将两张统计直接拼接。正式跨patch训练/对照应将精确support数量也作为配对条件，并报告排除率。

结论：已训练原型具有一定同片远区域迁移能力，且优于未学习原始token匹配，但三种模型均有迁移损失。下一步适合显式跨patch episodic训练，与同预算local训练配对比较；固定验证query/support，精确匹配标注数量，不能通过挑选更容易的support来制造提升。仍需后续跨片、缺失目标、真正点击与未知组织任务，不宣称当前已支持任意癌种/组织。

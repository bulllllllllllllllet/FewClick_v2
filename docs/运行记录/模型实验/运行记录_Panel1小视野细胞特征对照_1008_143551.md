# Panel1 小视野细胞特征对照

- 问题：现有128×128像素核中心图块是否过大、包含过多邻居；16/32/64像素图块能否更好表征目标细胞。
- 输入：2019-00538F已有固定空间划分的`panel1_train_all_0923_170500/cells.csv`，对应128特征缓存`panel1_train_all_features_0923_172500/features.npz`，另用固定均衡补充`panel1_eval_supplement_0923_155834/cells.csv`及其128特征缓存。只读已注册H&E PNG和HE核mask，核对源文件hash。
- 设计：train每类最多300细胞（淋巴类不足则全取），同一固定val/test和均衡补充val/test；所有视野在完全相同细胞上比较。核中心裁16/32/64像素，保留原目标核soft attention并统一resize到224输入冻结CTransPath-768；128视野直接用既有缓存。每个视野单独在train拟合L2归一化、StandardScaler与class_weight=balanced逻辑回归，选型只看val，测试指标作为已反复使用清单上的探索性描述。
- 另报每细胞核掩膜在16/32/64裁剪中保留面积比例；若16像素大量截断核，不能把模型下降解释为“小细胞形态无用”。16像素放大到224也可能偏离骨干预训练尺度。本次只试单细胞输入，不重新定义细胞边界。
- 防泄漏：空间组沿用原manifest；补充清单patch/空间组与train互斥；所有标准化与分类器仅在所选train拟合；原始源图和缓存只读。
- 输出：`/nfs-medical3/zyh/fewclick_v2/semantic_phase3/panel1_small_cell_crop_1008_143551/`，GPU1、CPU8线程，真实少量细胞smoke后用tmux运行正式任务、日志及`EXIT_CODE`。验收：真实图片/核mask加载、来源hash与目标核ID核对，有限特征、完整核面积统计、同名单每视野准确率/macro-F1及逐类F1。
- 状态：待运行。

## 真实 smoke 与正式运行

- `--smoke-per-class 2`真实50细胞执行通过：实际源PNG/mask哈希、目标HE核ID、三种小视野骨干前向、128缓存同名单分类器与评估路径均通过；输出`panel1_small_cell_crop_smoke_1008_143551`。50细胞中16像素裁剪7例核掩膜保留面积<90%，32/64像素均0例；smoke的分类指标样本过小，不作为结果。
- 正式命令：`conda run -n aligner python -m benchmarks.v5.tools.probe_crc_panel1_small_cell_crops --output /nfs-medical3/zyh/fewclick_v2/semantic_phase3/panel1_small_cell_crop_full_1008_143551 --device cuda:1 --train-per-class 300`。GPU1、CPU8线程，tmux会话`p1_smallcrop_1008`，同前缀`.log`末尾写`EXIT_CODE`。训练上限每类300、稀有类按现有159全取；主清单val/test及补充val/test全量不变。完成后核对核面积覆盖率与四臂同名单指标。
- 用户补充：可视化不同像素视野。额外从均衡补充val每类选核面积中位数附近的1例，并增加16px核覆盖率最低的1例，六行×四列并排16/32/64/128的同核中心原始H&E；黄色轮廓标目标核，标题显示该裁剪保留的核面积比例。模型实际输入会在这些裁剪上再做软注意力并统一resize224；可视化只用于展示空间视野，不以图判定类别正确。输出`panel1_small_crop_visual_1008_144145/crop_size_contact_sheet.png`及细胞CSV，CPU无GPU。

## 完整结果与可视化

- 正式对照`panel1_small_cell_crop_full_1008_143551`完成，日志`EXIT_CODE=0`。实际train每类300/300/159/300/300，共1,359；原val 693、原test 625、均衡补充val/test各250，总3,177个同名单细胞。16/32/64px新特征均为有限768维，128px复用既有同名单缓存；原图/mask逐图块hash、空间组隔离和目标核ID核对通过。
- 核掩膜保留面积<90%的细胞：16px为734/3,177（23.1%），32px为6/3,177（0.19%），64px为0。16px最差仅保留34.7%；上皮类有477/1,255低于90%。这说明固定16px对部分核已截断，不能代表完整单细胞形态。

| 核中心裁剪 | 原val accuracy / macro-F1 | 原test accuracy / macro-F1 | 均衡补充test accuracy / macro-F1 |
| --- | ---: | ---: | ---: |
| 16px | 0.573 / 0.350 | 0.656 / 0.395 | 0.332 / 0.320 |
| 32px | 0.580 / 0.377 | 0.632 / 0.402 | 0.380 / 0.368 |
| 64px | 0.564 / 0.356 | 0.648 / 0.370 | 0.344 / 0.336 |
| 128px | 0.537 / 0.353 | 0.598 / 0.355 | 0.368 / 0.369 |

- 原val按预设macro-F1选32px，较同名单128px高0.024；但均衡补充test的macro-F1两者近乎相同（0.368对0.369），不能宣称稳定泛化提升。原test淋巴内皮仅2例且已反复查看，表中该test数仅为探索性。均衡补充test每类50例，32px相对128的血管F1由0.233到0.327，但淋巴由0.378降到0.283、CAF由0.263降到0.209；收益并不覆盖全部五类。
- 本轮同时改变了原始裁剪大小以及统一resize224后的有效放大倍率；CTransPath预训练在较大病理图块上，不能把结果直接解释为“单细胞半径恰好32px”。目前更合理的是保留32px目标核视野与独立较大上下文视野两路，而不是全量替换128缓存。
- 所有分类分数仍是2019单病例、mIF规则派生弱标签上的空间留出探索，不代表独立人工真值或跨病例泛化。
- 可视化首跑`panel1_small_crop_visual_1008_144145`在PIL只读数组上绘制轮廓时报错，未生成图；复制成可写数组后正式输出`/nfs-medical3/zyh/fewclick_v2/semantic_phase3/panel1_small_crop_visual_1008_144519/crop_size_contact_sheet.png`及同目录`displayed_cells.csv`。图为五类各一个核面积中位数例，加一例16px截核明显的细胞；同一核中心四列裁16/32/64/128px，统一放大到224px显示，黄色为目标HE核轮廓。显示的是原始H&E裁剪，模型还会对该裁剪施加核软注意力。
- 状态：实验与可视化完成；建议下一步以32px目标核分支作为候选，在经过配准复核的更多空间区域/病例上重复，并与128及可选周边视野做同名单消融。

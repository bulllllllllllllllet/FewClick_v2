# CRC身份类别平衡训练

时间：2026-09-15 20:25:00。

问题：首轮非加权五类身份训练在2022封存病例上只预测CD4_T和CD163_Macrophage；2017训练病例标签频数为CD4_T 2,806、CD8_T 927、Treg 12、B_cell 1,356、CD163_Macrophage 2,717。

改动：身份阶段仅从train split的精确单标签细胞统计频数；采用effective-number权重`(1-β)/(1-β^n)`，`β=0.999`，均值归一后上限为5。权重只影响identity CE的每细胞贡献，不改变标签、图块、病例split、验证或test数据；多标签样本按允许类别平均权重，缺失类别直接拒绝训练。

输入与对照：固定全量manifest `crc_identity_phase3_manifest_0915_202108/`、与首轮完全相同的冻结Phase2/v4 baseline、seed、epoch上限和test病例。对照为`identity_0915_202109/`（test macro-F1 0.243927）。

计划：GPU1执行新的identity训练，采用2019病例选择checkpoint；随后一次性在2022封存病例评价。验收为：训练权重元数据仅含2017统计；loss有限、checkpoint指纹一致；报告五类F1、macro-F1、Brier和ECE。类别平衡若提升宏平均但恶化校准，将只保留为候选，不直接进入fusion。

第一轮结果：仅effective-number loss的`identity_0915_202502/`完成18个epoch，best val macro-F1为0.273469，低于非平衡基线0.274683；2022 test macro-F1为0.223774，低于基线0.243927，CD8/Treg/B_cell仍均为0。因此该候选被拒绝，不进入fusion。诊断显示2017训练病例的12个Treg只分布在4/12图块中；单纯细胞权重没有增加这些空间上下文的出现次数。

第二轮：保持权重只由train统计，额外采用train-only patch-level effective-number抽样。一个图块对每个出现的类别只计一次权重，避免图块内高频细胞数量再次淹没稀有类；含Treg的4个训练图块将以更高概率出现。该策略不读取val/test标签，且仍以2019选checkpoint、2022只在训练结束后评价。

第二轮结果：`identity_0915_202505/`在GPU1完成16个epoch，best val macro-F1为0.265748（epoch 3）；`evaluate_test_0915_202506/`的2022封存test macro-F1为0.208525、Brier 0.727482、ECE 0.245839，低于非平衡基线0.243927。CD4_T/CD163_Macrophage F1为0.366197/0.676430，CD8_T、Treg、B_cell依旧均为0。因此第二轮同样被拒绝，两个平衡候选均不进入fusion。

结论：类别不均衡的训练机制已实现并真实验证，但它不能弥补训练监督缺口：2017训练病例仅有12个Treg，且只分布在4个图块；2019/2022病例必须保持为val/test，不能被用于增加训练样本。下一步的有效方案是扩大**训练病例级**医生审核细胞样本（尤其CD8/Treg/B_cell），或在新增病例前先将身份任务降为现有可支持的粗粒度类别；不能靠复制、伪造、或回送已审核标签复核来声称解决五类泛化。

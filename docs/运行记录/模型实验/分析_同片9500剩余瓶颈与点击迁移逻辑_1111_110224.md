## 点击协议与内部实现

相同：一张支持图，3正2负同一组坐标；同片不同物理patch且full4x不重叠；query人工点0。所有11000任务点数现场核对。支持GT只产生已冻结模拟点；SANSA推理收到point prompt，不收到完整GT支持mask。统一最终>=.5评分。

FewClick：`architecture_bridge/deterministic_graph.py::support_task`从点处soft assignment加权region token，带多尺度上下文；query region对raw prompts注意力、任务相似度和图解码。`support_match_study/model.py::SignedMatcher`将256维dense embedding投影64维，用正负点descriptor对query生成正max/mean、负max/mean和正负差，再结合base概率/不确定性，7通道→1x1Conv32→1x1残差。保留的是少量区域上下文token和相似度摘要，不能说仅有孤立像素；该匹配残差没有额外邻域卷积，但上游已有上下文和图传播。完整support预测mask在训练受监督，却不作为query推理的记忆输入。

SANSA：`sansa_adaptation/model.py::_run`将support/query组成两个帧，shots=1，仅第0帧带point prompt。官方`models/sansa/sansa.py`每对重置memory；支持点→SAM mask decoder预测support区域→memory encoder结合区域预测与图像特征→query memory attention→原生mask decoder及高分辨率特征。query解码无point_inputs。无需图像相邻，也不把支持坐标复制到query，不累计其他评估任务的memory。公共先验/视野/编码分辨率不同，不能宣称架构信息完全相同；区域记忆是自动预测，不是额外人工监督。

## 推荐与验证顺序（planned，未执行）

1. 优先验证支持证据：固定train-only病例检查support mask质量、正负region混合、支持预测区域对query的影响。探索将可靠的预测正/负区域汇成多个空间token，而非只加单点256维细节。高置信核心与不确定边界分开，保留原点约束。仅用支持图/点击/模型预测形成证据；完整支持GT替换只能作为单独更强监督诊断，绝不进入少点击主表。风险是support错误传播及FPA上升。
2. 匹配与组织区分：当前max/mean相似度压缩可能丢失多模态组织外观和对应结构，属于代码支持的待测假设。控制encoder不变，对多原型区域证据或query对支持空间token注意力作单因素对照；显式保留负证据。困难负例必须由train池产生，不按当前query GT挑点。比较正常间质/腺体、浆膜/肌肉及背景误报。
3. 查询侧细化：在正确匹配条件下检查内部漏分、边界偏移、孔洞/连通性，再决定task-conditioned细化。当前point_detail仅改support token，不等于query高分辨率refiner；历史另一像素头已未晋升，不能原样重复且假定有效。风险是扩大边界同时误分背景，必须同时守FPA/淋巴/脂肪及边界指标。
4. 低优先级：直接换encoder、重开细胞词表、无限加步数。现有细节臂总体无收益；旧仅替换SAM2 encoder负结果不能否定全部SAM2方案，却也不足支持再次直接替换。先隔离证据/匹配/细化瓶颈，再定预算。

统一验收：同9500训练监督、同支持点和同片零query人工提示；固定checkpoint/阈值；保持完整类别和absent FPA。任何新改动先训练功能门控，再完整评估，并按既有质量门槛判定。未宣称必定反超；single seed、暴露开发集、同片相关性及稀有类任务数限制保留。

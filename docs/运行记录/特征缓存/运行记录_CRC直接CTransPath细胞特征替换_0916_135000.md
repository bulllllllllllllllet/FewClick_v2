# CRC 直接 CTransPath 细胞特征替换

## 目的

现有身份训练使用冻结 XCell 的`reg64`，其链路为`H&E → CTransPath-768 → XCellFormer → reg64`。多个类别平衡和空间摘要对照均未使CD8_T/Treg稳定可分。本轮改为直接从相同H&E细胞 crop 提取冻结 CTransPath-768，绕过 XCell 的64维压缩，检验视觉特征本身是否是瓶颈。

## 可访问性核验

`/nfs-medical5` 已恢复为NFS4挂载；已实际读取医生审核缓存所指向的`2017-23800D/registered_he_patches/x35328_y10240.png`（567,221 bytes）。父目录不可枚举不影响已知CRC路径读取。

## 计划与纪律

- 先以3个真实图块做完整 smoke：原始H&E、Cellpose对应细胞ID/坐标、相同128px crop、CTransPath CLS/pooled 768维、有限性与行ID对齐。
- smoke通过后，对当前1,553图块的**同一H&E检测细胞**重建派生特征缓存；不修改原始图像、XCell缓存、mIF标签或既有身份契约。
- 仅以已经医生审核并成功转移的五类身份标签监督新分类头；train/val图块划分固定，与DRW基线公平A/B。
- CTransPath-768失败或不优于`reg64`后，才启动Phikon-v2双尺度 crop，不将两种backbone混合为不可归因的方案。

## 验收

特征必须同现有`he_cell_ids`逐项对应、数值有限、图块SHA可追溯，且不读取mIF marker作为模型输入。身份训练以patient macro-F1和五类precision/recall/F1与DRW 0.221140比较；仍仅为同病例内部图块验证。

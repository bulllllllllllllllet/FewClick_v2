## 1. 审计范围与结论

- 审计时间：2026-09-09 16:52:50 CST
- 只读数据根：`/nfs-medical6/data/SRRSH/crc/`
- 审计方式：逐层列举目录与文件大小；读取全部根级/标注级 JSON、规则和染色说明；读取三份大 TSV 的表头及首行样本；以各 `*_summary.json` 的细胞计数与类别计数作完整性核对；检查 QuPath 项目、H&E 肿瘤 GeoJSON 和关键配准矩阵。未修改 NFS 原始数据。

这是一个 **3 例 CRC 病例、两套 8 通道 mIF panel、配对 H&E WSI、细胞级空间表型与跨模态配准产物** 的内部队列，而不是 RNA/空间转录组数据。其最强用途是 H&E–mIF 配准、细胞/组织微环境弱监督、跨 panel 空间邻域分析；不应将其描述为“病理–基因表达配对队列”。本地资料目录中的通用资源目录 CSV 只登记了公开 10x Visium CRC 等条目，未登记此 `SRRSH/crc` NFS 数据，因此该队列目前缺少目录化的数据所有者、伦理/使用边界、病理诊断与病例级临床元数据记录。

## 4. mIF panel、生物学含义与标注规则

### panel_1：结构/间质/上皮 panel

通道顺序固定为 `DAPI, Opal570, Opal690, Opal480, Opal620, Opal780, Opal520, Sample AF`，映射为 `DAPI, CD31, FAP, S100, D2-40, CKPAN, SMA, AF`。

- `CKPAN+` 优先判为 Epithelial；其余细胞先判 CD31/D2-40（血管、淋巴或 D2-40+），再判 FAP/SMA（CAF、肌成纤维/平滑肌）。
- S100 是附加状态而不是确定谱系；它会追加 `_S100`。DAPI 仅作核分割，不进入 identity gate。
- 每 marker 的细胞强度是“核均值”和“非重叠 4 px 核周 ring 均值”的较大值；这解释了大表中 `_nuclear_mean`、`_ring_mean`、`_intensity` 三组字段。
- 39941E 的 `panel1_manual_thresholds.json` 明确复用 `CRC_1` 阈值，存在跨切片统一阈值的可比性优点，也有染色批次偏移风险。

### panel_2：免疫/SULF1 panel

同一 QPTIFF 顺序映射为 `DAPI, CD20, CD4, CD163, CD8, SULF1, FOXP3, AF`。阳性阈值（下限）为 CD20 150、CD4 300、CD163 232、CD8 100、SULF1 500、FOXP3 1500。

- CD4/CD8/CD20/CD163 是竞争性的主身份；多阳性时选提取强度最大的 marker。
- 主身份 CD4 且 FOXP3+ 才为 Treg；FOXP3 单独阳性被明确保留为 unresolved。
- SULF1 只作为共表达后缀，不与主身份竞争；无主身份而 SULF1+ 为 `SULF1_only`。
- 规则文档称“阳性范围”，实际 summary/JSON 使用的是 `minDisplay` 下限进行 positive call；没有看到把 maxDisplay 作为上限排除的证据，应在复现脚本中显式确认。

## 5. 大型 TSV/JSON 抽读与细胞标注完整性

早期检查以大型 TSV 为主，不能据此断言全目录没有 CSV。确认列出的三份明细表约372、311、274 MB，简表约54、46、40 MB；实际读到了CRC_1明细表头/样本和三份简表头/样本，并完整读取三份summary及相应规则/配置。CRC_1明细表为 **38列**：`patch_name, cell_id, x, y, area_px`，8个通道各3个强度字段，6个阳性flag，以及`base_cell_type, cell_type, retained_coexpression`；不能直接假定不同panel同列数。简表为`x,y,class`，不能恢复强度或patch身份。

| 标注集 | 总表/简表 | summary 细胞数 | 处理 patch 数 | 主要类别（数量；占总细胞） | 计数核验 |
|---|---:|---:|---:|---|---|
| `panel_1/CRC_1_cell_annotation` | 372 / 54 MB | 1,210,012 | 7,055 | Undefined 720,083 (59.51%)；Epithelial 272,884 (22.55%)；SMA_stromal 63,251 (5.23%)；D2-40+ 39,188 (3.24%)；Blood_endothelial 33,277 (2.75%) | 类别和 = 1,210,012，差 0 |
| `panel_1/22-39941E_cell_annotation` | 311 / 46 MB | 1,004,897 | 18,228 | Undefined 455,104 (45.29%)；D2-40+ 185,988 (18.51%)；Epithelial 155,814 (15.51%)；Lymphatic_endothelial 50,768 (5.05%) | 类别和 = 1,004,897，差 0 |
| `panel_2/20260706-sulf1_cell_annotation` | 274 / 40 MB | 885,563 | 10,092 | Undefined 486,200 (54.90%)；CD163_Macrophage 159,056 (17.96%)；CD163_Macrophage_SULF1 63,670 (7.19%)；CD4_T_SULF1 49,032 (5.54%)；CD8_T_SULF1 42,977 (4.85%)；CD8_T 39,753 (4.49%) | 类别和 = 885,563，差 0 |

三份 JSON 的 `n_cells` 与 `cell_type_counts` 求和均严格一致，因此**类别汇总在内部算术上是自洽的**。但这不等价于生物学金标准：Undefined 占 45–60%，且类别来自固定阈值/层级规则，适合作为弱标签或候选 ROI，不应直接当作人工逐细胞真值。

各annotation目录还有`cell_tables/`与`segmentation_masks/`，文件名含mIF切块坐标。列表中看到1 B的cell table和约824 B的小mask，另有190–209 KB的表；文件大小不足以证明mask为空，需要实际解码检查。统计有效patch不能只按文件数量；补充目录不能在未确认来源和重复关系前与39941E主集直接合并。

## 7. 审计发现、风险分级与建议

| 等级 | 发现 | 影响 | 建议动作 |
|---|---|---|---|
| 高 | `panel_1/mIF/22-39941E(FAP)/Scan1/` 有 47 GB `*.baiduyun.p.downloading` | 未完成下载副本可能被通配符/批处理误读，且显著夸大占用 | 所有扫描脚本排除 `*.downloading`；确认完成文件的校验和后再纳入 |
| 高 | 病例标识不一致：`17/19/22-...`、`2017/2019/2022-...`、`CRC_1`、`20260706-sulf1` 并存 | 易发生错误配对、数据泄漏或把重扫当新病例 | 建立只读 manifest：canonical case ID、切片/scan ID、panel、模态、配准版本、是否同一组织层面 |
| 高 | 仅 3 个病例，且一些同例跨 panel/重扫产物 | 若按 WSI/patch 随机划分，必然泄漏病例特征 | 任何建模按 canonical case 分组；目前最多 3-fold leave-one-case-out，不能宣称稳健泛化 |
| 中 | 细胞类来自阈值和优先级规则；Undefined 45–60% | 标签是规则型弱监督，类别边界受阈值/染色漂移影响 | 抽取每类/每例人工 QC；记录阈值版本，建模时保留 confidence/Undefined 而非强行丢弃 |
| 中 | 全局仿射配准分数约 0.71–0.83，切片之间可能存在组织形变 | 全图转换不可直接承担细胞级 pixel-aligned supervision | 优先用 patch/local registration；报告 landmark 误差或 overlay 人工验收 |
| 中 | tile 级目录混有大量空 TSV/mask | 文件计数会虚增样本量，空 tile 会污染训练枚举 | 以总 TSV 行/非空 tile/组织 mask 作为有效样本定义，并写入 manifest |
| 中 | QuPath URI 使用旧 Windows/不同 NFS 路径 | 项目在当前环境可能打不开或链接到错误位置 | 复制项目到工作区前先备份并在副本中更新 URI；不要编辑 NFS 原项目 |
| 低 | panel_1 同时保存 KFB 与 SVS | 可能为重复表示，存储/训练抽样会重复 | 用尺寸、金字塔元数据和缩略图验证后指定一种 canonical H&E 格式 |
| 低 | 根目录没有病例临床/病理诊断/伦理说明 | 无法进行预后/分期/疗效结论，也难以审计数据权限 | 补充受控元数据表和数据使用说明；与图像数据分开管理敏感信息 |

## 9. 建议的最小数据契约

后续使用前应在工作区创建**不含原始像素复制**的 manifest，至少包含：`case_id`、`section_id/scan_id`、`panel`、`modality`、`source_path`、`coordinate_system`、`pixel_size_um`、`marker_mapping_version`、`threshold_version`、`cell_annotation_version`、`registration_transform_path`、`registration_qc_status`、`tumor_roi_path`、`split_group`、`known_caveat`。所有训练/缓存清单应从该 manifest 派生，并显式排除 `.downloading`、`.lock`、`.temp` 与空 tile。

## 10. 审计边界

本次没有对数十 GB QPTIFF/SVS 做全像素解码、没有重新计算细胞分割、没有逐个 tile 全量读表，也没有将配准矩阵应用到所有细胞坐标；上述工作会造成长时 I/O，且属于后续数据验证而非目录审计。因而本报告确认的是文件存在性、格式/元数据、规则逻辑、汇总计数自洽性及明显风险，不把它表述为图像内容或配准精度的最终验收。
